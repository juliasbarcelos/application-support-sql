INC-001 — Encomenda pendente com pagamento aprovado

Projeto: Application Support Portfolio
Categoria: Suporte Aplicacional / Investigação SQL
Ambiente: MySQL — Base de dados simulada
Estado: Em investigação
Data: 13/10/2026

1. Descrição do incidente

Foi identificada uma inconsistência na encomenda 1002, associada ao cliente fictício Bruno Costa.

O pagamento de 79,99 € encontra-se aprovado, mas a encomenda permanece com o estado "Pendente".

2. Objetivo da investigação

Verificar a consistência entre os dados das encomendas e dos pagamentos, identificar outros possíveis registos afetados e recolher evidências para investigar a causa.

3. Procedimentos realizados

Consulta 1 — Verificação dos estados

Foi utilizada uma consulta SQL com INNER JOIN para relacionar as tabelas clientes, encomendas e pagamentos.

Resultado: Identificada a encomenda 1002 com pagamento aprovado e estado pendente.

Consulta 2 — Validação dos valores

Foi executada uma consulta para identificar pagamentos aprovados cujos valores fossem diferentes dos valores das respetivas encomendas.

Resultado: Nenhuma divergência encontrada nos registos analisados.

Consulta 3 — Análise geral das encomendas

Foi utilizada uma consulta com LEFT JOIN para verificar todas as encomendas e respetivos pagamentos.

Resultado: Três encomendas analisadas. Apenas a encomenda 1002 apresentou a inconsistência de estados identificada.

Consulta 4 — Análise da estrutura das tabelas

Foi utilizado o comando DESCRIBE para analisar as estruturas de encomendas e pagamentos.

Resultado parcial: A tabela encomendas contém o campo data_encomenda e utiliza "Pendente" como estado predefinido. Não foi identificado um campo de data da última atualização nesta tabela.

4. Diagnóstico preliminar

Foi confirmada uma divergência entre o estado da encomenda e o estado do pagamento.

Uma hipótese é que o processo responsável pela atualização do estado da encomenda não tenha sido executado corretamente.

Esta hipótese ainda não foi confirmada.

5. Próximas ações

Analisar a estrutura completa da tabela pagamentos.

Verificar os dados temporais disponíveis.

Investigar possíveis falhas no processamento da atualização de estados.

Documentar as evidências e a conclusão técnica.

6. Estado atual

Investigação em curso.

Nenhuma alteração foi realizada nos dados da base de dados.
